This commit introduces the complete RShell syntax layer, a major milestone that adds
automatic line-based mode detection, structured data types, and a comprehensive
Tree-sitter grammar for parsing .rsh files.

## RShell Syntax Features

RShell extends Bash with modern programming constructs while maintaining full
shell compatibility:

- **Structured Data Types**: Native lists `[1, 2, 3]` and maps `{key: "value"}`
- **Type-aware Expressions**: Automatic type inference and coercion
- **Pipeline Integration**: Seamless data flow between shell commands and expressions
- **Control Flow**: Enhanced if/for/while with expression support
- **Function Definitions**: Named functions with parameters and return values
- **String Interpolation**: Advanced `"text ${expr}"` and `"cmd $(subcmd)"` syntax

## Tree-sitter Grammar Implementation

- `rshell-grammar/src/scanner.c` (214 lines): Custom external scanner

**External Scanner:**
The custom C scanner implements context-sensitive parsing with line-based mode
detection, allowing RShell to automatically switch between:
- **EXPR mode**: For assignments, structured data, and expressions
- **CMD mode**: For shell commands and pipelines

This intelligent mode detection eliminates the need for explicit syntax markers,
making RShell code clean and natural.

## Line-based Mode Detection

The scanner analyzes line beginnings to determine parsing context:

```rsh
# EXPR mode - variable assignment
result = [1, 2, 3]

# CMD mode - shell command
echo "Hello"

# EXPR mode - map construction
config = {port: 8080, host: "localhost"}

# CMD mode - pipeline
cat file.txt | grep "pattern"
```

**Detection Rules:**
- Lines starting with identifiers followed by `=` → EXPR mode
- Lines starting with `if`, `for`, `while` → Control flow parsing
- Lines starting with commands → CMD mode
- Automatic context restoration after control structures

## Known Limitations (Phase 3)

Two tests currently fail for multiline structures:
- Multiline list definitions `[1,\n2,\n3]`
- Multiline map definitions `{key:\n"value"}`

**Root Cause**: Tree-sitter's external scanner is called before the parser consumes
tokens, making bracket depth tracking infeasible. Single-line syntax works perfectly.

**Workaround**: Use single-line syntax: `[1, 2, 3]` and `{key: "value"}`

**Phase 3 Plan**: Explore grammar-based solutions or parser state tracking.

## Breaking Changes

This commit introduces the `.rsh` file format with new syntax. Existing Bash scripts
remain fully compatible when run through the shell command mode.

**Migration Path:**
1. Bash scripts continue to work as-is in CMD mode
2. New .rsh files can mix Bash commands with RShell syntax
3. Gradual migration: add structured data types where beneficial
4. Full backward compatibility maintained
